## The carve (verified by source map)

The four MM core libs have **zero** RT64 dependency. RT64 is linked in exactly one place:
the `Zelda64Recompiled` executable (`CMakeLists.txt:347`). The concrete RT64 renderer lives
only in `src/main/rt64_render_context.cpp`; everything else is renderer-agnostic.

```
Zelda64Recompiled ─┬─ PatchesLib       (include-only; needs patches.elf MIPS build)
                   ├─ RecompiledFuncs   (generated MIPS→C; include-only)
                   ├─ librecomp ──┬─ ultramodern, N64Recomp, LiveRecomp, miniz
                   ├─ ultramodern (declares the abstract RendererContext only)
                   └─ rt64            ◄── ONLY RT64 edge — replace
```

- ultramodern: `lib/N64ModernRuntime/ultramodern/CMakeLists.txt:7`, links nothing.
- librecomp: `lib/N64ModernRuntime/librecomp/CMakeLists.txt:8`, links ultramodern/N64Recomp/
  LiveRecomp/miniz. No RT64.
- RecompiledFuncs: top `CMakeLists.txt:69`, sources `RecompiledFuncs/*.c` (glob 85-88).
- PatchesLib: top `CMakeLists.txt:91`, sources `RecompiledPatches/patches.c` + `patches_bin.c`
  (107-110), generated by `N64Recomp patches.toml` after a MIPS `patches.elf` build
  (`patches/Makefile`, needs **clang -target mips** + **ld.lld**; dnf-installable, not yet
  installed). mm-decomp submodule + `Zelda64RecompSyms/mm.us.rev1.*` are present.

## The renderer seam (what we implement)

`ultramodern::renderer::RendererContext` (pure virtual,
`.../ultramodern/include/ultramodern/renderer_context.hpp:75`). 8 pure virtuals:
`valid`, `update_config`, `enable_instant_present`, `send_dl`, `update_screen`, `shutdown`,
`get_display_framerate`, `get_resolution_scale`. Ctor `(uint8_t* rdram, WindowHandle, bool dev)`.

Factory registered at `src/main/main.cpp:685` via `callbacks_t{ .create_render_context = … }`.
Dispatcher is renderer-agnostic in `ultramodern/src/renderer_context.cpp`.

- **RDRAM**: no global. `uint8_t* rdram` (512 MB committed, 4 GB reserved; mmap in
  `librecomp/src/recomp.cpp:785`) is passed straight to the factory. Our `send_dl` view base =
  `rdram`; DL phys offset = `task->t.data_ptr & 0x3FFFFFF`. Our `n64dl::RdramView(rdram, 8MB)` +
  `Transcoder.transcode(task->t.data_ptr)` (resolve() already masks KSEG0/segment). ucode at
  `task->t.ucode & 0x3FFFFFF` identifies F3DEX2 (assumed; assert later).

- **Threading (clean)**: `create_render_context`, `send_dl`, `update_screen` ALL run on the
  gfx thread (`ultramodern/src/events.cpp:332/370/378`). So the entire libultraship renderer
  lives on one thread — matches its single-thread model. Bring up libultraship in the context
  ctor (on the gfx thread), drive it from send_dl/update_screen.

- **Frame mapping**: soh3d's `Fast3dWindow::DrawAndRunGraphicsCommands` is atomic
  (StartFrame→Run→EndFrame→present). N64 model is N send_dl (gfx tasks) then one update_screen
  (VI swap). FIRST CUT: send_dl = transcode + DrawAndRunGraphicsCommands (draw the frame);
  update_screen = no-op. Works when one gfx task/frame (title screen). Multi-task-per-frame is a
  known limitation to revisit (would need StartFrame/Run.../EndFrame split — those are public on
  Fast3dWindow).

## The SDL2/SDL3 problem (architectural crux)

Zelda64Recomp links **SDL2** (window in `src/main/main.cpp`, input in `src/game/input.cpp` —
231 SDL refs, UI in `src/ui/*`). libultraship links **SDL3**. Both export the same `SDL_*`
symbols with different ABIs — they CANNOT co-link.

Resolution (chosen): do NOT compile the recomp's SDL2 host (`src/main/main.cpp`,
`src/game/input.cpp`, `src/ui/*`). Instead write **zelda3d's own host main** that:
  - replays main()'s essential, renderer-agnostic registration sequence (register_game(MM),
    register_overlays, register_patches, init_extended_actor_data, load_config, REGISTER_FUNC
    exports), then `recomp::start(...)` with our callback set, then `recomp::start_game`.
  - provides our own `gfx_callbacks` (create_window returns libultraship's SDL3 window / or a
    headless handle — NOT an SDL2 window), `input_callbacks` (SDL3 or stub for first boot),
    `audio_callbacks` (the recomp's SDL audio — check SDL2 vs SDL3; audio.cpp uses SDL).
  - our `create_render_context` → SoH3DRenderContext.
Compile the renderer-agnostic game glue from src/game (recomp_api, recomp_actor_api,
scene_table, config, …) + src/main/register_overlays.cpp + register_patches.cpp. Audit which
of those pull SDL2/UI.

NOTE audio.cpp in ultramodern uses SDL (1 ref) — check whether SDL2 or SDL3 there.

## ROM provisioning

Game id `mm.n64.us.1.0`, rom_hash `0xEF18B4A9E2386169`. The runtime expects a hash-validated
decompressed copy in the config dir as `mm.n64.us.1.0.z64` (written once by `recomp::select_rom`).
Bypass the UI: call `recomp::select_rom(path, "mm.n64.us.1.0")` once, then
`recomp::start_game(u8"mm.n64.us.1.0")`. Our `.env` has `$ZELDA3D_MM_ROM`.

## 4c boot recipe (verified source map, 2026-07-01) — the exact host-main surface

`recomp::start(...)` blocks the calling thread forever (spin loop, `recomp.cpp:818`). Signature
(`librecomp/include/librecomp/game.hpp:92`): `start(const Version&, WindowHandle window_handle,
rsp_callbacks, renderer_callbacks, audio_callbacks, input_callbacks, gfx_callbacks,
events_callbacks, error_handling_callbacks, threads_callbacks)`. Only **rsp_callbacks** (its one
member `get_rsp_microcode`) and **renderer_callbacks.create_render_context** are mandatory;
everything else is null-checked and stubbable.

**Host main must (in order):**
1. `recomp::Version` project version (`Version::from_string`).
2. `recomp::register_config_path(zelda64::get_app_folder_path())` — BEFORE select_rom/start
   (start calls check_all_stored_roms first thing).
3. Fill + `recomp::register_game()` the MM `GameEntry` (game.hpp:21). Fields = the main.cpp:351
   table: rom_hash `0xEF18B4A9E2386169`, game_id `u8"mm.n64.us.1.0"`, mod_game_id `"mm"`,
   save_type Flashram, decompression_routine `zelda64::decompress_mm`, has_compressed_code true,
   entrypoint_address `get_entrypoint_address()`, entrypoint `recomp_entrypoint`.
   - `recomp_entrypoint` → RecompiledFuncs/funcs_0.c; `get_entrypoint_address` →
     RecompiledFuncs/lookup.cpp (returns 0x80080000); `decompress_mm` → src/game/rom_decompression.cpp.
4. `zelda64::register_overlays()`, `zelda64::register_patches()`,
   `recomputil::init_extended_actor_data()`, `recomputil::register_data_api_exports()`,
   `zelda64::load_config()`, and the 13 `REGISTER_FUNC(recomp_get_*)` base exports
   (register_base_export pattern, main.cpp:569/660-674; getters in src/game/recomp_api.cpp).
5. Reproduce `get_rsp_microcode` (main.cpp:333): M_AUDTASK→aspMain, M_NJPEGTASK→njpgdspMain
   (extern RspUcodeFunc from rsp/*.cpp) → rsp_callbacks.
6. Callbacks: renderer.create_render_context = mm_host::create_render_context (MANDATORY);
   audio = no-op (queue_samples no-op, get_frames_remaining→0, set_frequency no-op); input =
   nulls (or get_input→false); gfx: pass a NON-`{}` window_handle to start() so create_window is
   never called (leave it null), update_gfx = null or our SDL3 pump; events/threads = null;
   error_handling.message_box = stderr.
7. Stub the `recompui::*` free functions the compiled game files call (they normally live in
   src/ui/, which we don't compile): `activate_mouse, drop_files, get_window_size,
   is_context_capturing_input, message_box, process_game_started, queue_event,
   set_cursor_visible, toggle_fullscreen`, plus `recompui::register_ui_exports` (no-op).
   get_window_size → our framebuffer size; message_box → stderr; rest no-ops.
8. On a SEPARATE thread: `recomp::select_rom(romPath, id)` (id is a non-const `std::u8string&`,
   validates hash + caches an uncompressed copy under config_path) then `recomp::start_game(id)`
   (flips the atomic the game thread waits on). Then call `recomp::start(...)` on main thread.

**WindowHandle** is pure passthrough — the ONLY dereference is `create_render_context(rdram,
window_handle, dev)` at events.cpp:332. Nothing in librecomp/ultramodern touches it for VI/events/
resize. So pass a non-null dummy (skips create_window) and ignore it in our factory.

**Files to compile (all renderer-agnostic, NO SDL2 — verified by include grep):**
`src/game/{rom_decompression,config,controls,recomp_api,recomp_data_api,recomp_actor_api,
scene_table}.cpp` (+ optional debug.cpp, quicksaving.cpp), `src/main/{register_overlays,
register_patches}.cpp`, `rsp/{aspMain,njpgdspMain}.cpp`. The ONLY SDL2/RmlUi files are
`src/main/main.cpp`, `src/game/input.cpp`, `src/ui/*` — exactly the ones we exclude.

**Clang gate:** `register_patches.cpp` #includes generated `RecompiledPatches/patches_bin.h` +
`recomp_overlays.inl` → needs the PatchesLib build (4a.2, clang/lld). So the host can't fully
compile/link until clang is installed. Everything else (host main, game-glue, stubs, factory)
can be written + compiled first; patches slot in at the end.

## 4c IMPLEMENTED (2026-07-01) — written + compile-verified, link/run pending clang

Landed under `src/mm_host/` and wired into `src/mm_host/CMakeLists.txt`:

- **`mm_main.cpp`** — the host main. Replays main()'s renderer-agnostic registration
  (register_config_path → register_game(MM) → base exports → register_ui_exports(shim) →
  register_data_api_exports → register_overlays/patches → init_extended_actor_data → load_config),
  builds the callback set (our `mm_host::create_render_context`, no-op audio/input, stderr
  message_box), passes a **non-null sentinel WindowHandle** (`(SDL_Window*)1`) so `recomp::start`
  skips create_window, and kicks `select_rom($ZELDA3D_MM_ROM, u8"mm.n64.us.1.0")` +
  `start_game` from a detached thread before `recomp::start` blocks the main thread.
- **`shim/recomp_ui.h`** — narrow host replacement for the upstream RmlUi/SDL2 `recomp_ui.h`. Sits
  FIRST on the game-glue include path so `#include "recomp_ui.h"` resolves to ours. Declares only
  the `recompui::` surface the compiled TUs touch (`get_window_size`, `message_box`,
  `register_ui_exports`). Matches the upstream `__RECOMP_UI__` guard.
- **`recompui_stubs.cpp`** — host impls of those three (`get_window_size` → fixed 1280×960 until the
  render context exposes a thread-safe size; `message_box` → stderr; `register_ui_exports` → no-op).
- **`renderer_stubs.cpp`** — the one `zelda64::renderer::` symbol the glue calls that upstream lives
  in the excluded `rt64_render_context.cpp`: `RT64HighPrecisionFBEnabled()` → false.
- **`mm_game_glue` static lib** — compiles the renderer-agnostic slice (the file list above minus
  `register_patches.cpp` until patches exist). Key build facts discovered:
  - `-march=nehalem` REQUIRED (rsp/*.cpp → `rsp_vu_impl.hpp` uses SSSE3 `_mm_shuffle_epi8` that
    won't inline at the default ISA); also `-fms-extensions -fno-strict-aliasing`.
  - Include set: shim, Z64R `include`, ultramodern/librecomp/N64Recomp includes,
    `lib/N64ModernRuntime/thirdparty` (json/json.hpp), `lib/concurrentqueue`,
    `lib/GamepadMotionHelpers`, `lib/SlotMap`, `lib/rt64/src` (header-only
    `common/rt64_user_configuration.h` via `zelda_render.h`).
  - **miniz**: `librecomp/mods.hpp` → `miniz.h` → generated `miniz_export.h` + `MINIZ_STATIC_DEFINE`.
    Don't hardcode the source dir — `target_link_libraries(mm_game_glue PRIVATE miniz)` propagates
    the generated include dir AND the static define via usage requirements (no objects archived).
- **`mm_host` executable** — gated on `TARGET mm_host_render AND _have_patches`. Links
  mm_game_glue + mm_host_render + `--whole-archive RecompiledFuncs PatchesLib --no-whole-archive`
  (the generated cores are reachable only through the overlay tables, so whole-archive is required)
  + librecomp + ultramodern. Skipped with a clear message until clang/lld generate PatchesLib.
