# RE control/debug backlog — N64-side decomp gaps that block sweep coverage

See also: **`docs/re-frontier.md`** (the `player-link`/`mm-player` areas integrate the HIGH/MEDIUM
items below by reference — don't duplicate rows between the two docs) and **`docs/codemap.md`**.

**Purpose:** a durable, greppable registry of concrete RE items on the N64-side decomp SoH ships
in-tree (`Shipwright/soh/src/...` for OoT, `2ship/...` for MM) that — if further
reverse-engineered/named/documented — would unlock either a better **CONTROL** primitive (force
more states reliably, drive a native path instead of bypassing it) or a better **DEBUG** readout
(read internal engine state cleanly) for the parity sweeps (`tools/link_sweep.py`,
`tools/parity_state_sweep.py`, and any future MM equivalent).

**Scope note:** this is about the N64 decomp SoH vendors (control/observe surface), NOT the
`oot3d-decomp`/`mm3d-decomp` 3DS submodules (ground-truth ROM decomp) — see
`soh3d-decomp-is-ground-truth` memory / CLAUDE.md for that separate, primary RE track. This
backlog is downstream of that: once ground truth is known, these items are what make DRIVING and
OBSERVING the N64-side re-implementation reliable enough to sweep headlessly.

**How to use:** consult before re-deriving a control/debug gap. When you close an item, flip
Status to DONE, add the commit hash, and leave the row (don't delete — negative/closed history is
signal). Add new rows in the same shape when a sweep session hits a fresh gap. Rank by leverage —
most-sweep-unlocking items first within each area.
